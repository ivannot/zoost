Before you take my word for any of it

Everything on this page is a claim. Have it read back to you - all of it, by a machine, without installing anything.

Zoost is small, and it is published exactly as it was written: nothing packed, nothing hidden. So an assistant can read the whole of it and tell you what it found. Copy the box below into whichever one you already use - ChatGPT, Claude, Gemini, Copilot, any of them. You do not need to understand what is inside the box; it is addressed to the machine, not to you.

It asks three questions, for three different people: what is this and is it worth ten minutes, what can it actually do for somebody who works in Zoho all day, and what does somebody who has to approve it need to know. In that order, because that is the order the questions turn up in. And it asks where the answers do not match what is promised, because a prompt fishing for compliments would be worth nothing.

It points at two places, because the comparison is the point: the promises are on this site, the answers are in the code, and one checking the other is worth more than either alone. Assistants differ in what they can open, so it asks for that first - use both if you can reach both, one if only one, and say which. And if it can reach neither, stop: one that has read nothing will answer anyway, from memory, and that answer looks exactly like a real one.

Look at these two and describe what you find at three levels.

The code:    https://github.com/ivannot/zoost
             (two Chrome extensions: apps/crm and apps/analytics)
The promises: https://zoost.it

Start by saying which of the two you were actually able to open. If only
one, use that one and say so. If neither, stop there - do not answer
from what you already know about it.

1. In plain language, for somebody who does not write code:
   what is it, who is it for, what changes for them if they install it,
   and would you tell them it is worth ten minutes?

2. For somebody who works in Zoho every day:
   what can it actually do - the capabilities you find implemented, not
   the ones described; where is it weak; what would frustrate them on a
   large, untidy organisation; and would you recommend it to them?

3. For whoever has to approve it:
   what leaves the machine and when, which hosts it can reach, whether
   anything writes back to Zoho, what it stores and where.

Then finish with three things: anything promised - on the site, in
README.md, or in the description inside either manifest.json - that the
code does not have; what you cannot decide by reading alone; and what
you would want to test in a running browser.

The last question in the box is the one to read carefully. Reading tells you what a program is built to do; it cannot tell you what Zoho will answer tomorrow, or what somebody does with a file once they have saved it - and an assistant will sound just as sure either way, so it is asked to say where its answer stops. If you want the technical version, with every claim taken apart one at a time, it is on the nerd page.

What every Zoost has in common

It only reads

No Zoost calls an endpoint that creates, edits or deletes anything in Zoho. You keep working where you already work; this is the window onto it.

Plain files, your Git

A folder you choose, filled with ordinary files. Put it under version control and git diff answers what changed last month - which neither product can answer about itself.

The whole thing at once

Search everything together, follow a name to where it is used, and hand the lot to a colleague as one document.

Numbers without a grade

You get counts and lists, never a score. A four-hundred-line function may be a perfectly clean mapping table, and only you know which of yours those are. Every figure says what it does not cover, right beside itself.

Nothing leaves on its own

No account, no telemetry, and no server between you and your org. Two things leave only if you send them: what you ask the optional AI assistant, with your own key - what it adds, and when it is not worth one - and a problem report, which you read in full first.

Checkable, not just claimed

GitHub builds each release from a tagged commit, twice over, and signs it. The archive on the Release is the file sent to the Store - and one command tells you whether that is true.

Free, open, and yours to fork

Apache-2.0, no build step, no dependencies. Readable by anyone about to give it access to their data - which is what you are being asked to do.

One client, or fifteen

The org does not have to be yours. One working folder holds every client at once, each bound to the org, host and instance it came from. Point the browser at the wrong tab and everything that touches Zoho switches off until the two agree. Production and sandbox count as two.

Want the detail - which endpoints, what breaks it, how a release is signed? It is all on the nerd page, which is where it belongs.

Built and maintained by one person, with substantial help from Claudio on design, code and wording. The judgement calls, and the responsibility for the result, are mine.

If you have to approve it

Somebody has asked you whether they can install a browser extension that reads the company's Zoho CRM, or its Zoho Analytics. Seven lines.

What it readsConfiguration only: code, field definitions, automations, the structure of a workspace. Never the data itself - in Zoho CRM no contacts, no deals, no notes; in Zoho Analytics never the rows inside a table.
What it writesTo Zoho, nothing: it calls no endpoint that creates, edits or deletes. One call is a POST, and its URL says CREATE - ZDBCreateERD.ma, which returns a Zoho Analytics workspace's ER model and is the call that product's own diagram screen makes. It is named here rather than left to be found: what a browser can state is what Zoost sends, never what a server does with it. Endpoint by endpoint on the nerd page.
Where the data goesA folder on that person's own computer. No account, no telemetry, and nothing sent anywhere unless they send it: a question to an AI provider, or a problem report they have read in full.
The one exceptionAn optional AI assistant, off until someone enters their own API key. Then, and only then, the parts it needs go to Anthropic or OpenAI. It can reach nowhere else.
What it can seeExactly what that person can already see in Zoho. It uses their session and their permissions, and can do nothing they could not do.
What it asks Chrome forFour permissions - sidePanel, storage, scripting, tabs - and a named list of hosts, never <all_urls>. Both ask for their own platform's domains in every data centre, api.anthropic.com / api.openai.com, and zoost.it. Zoho CRM adds its sandbox data centres and the Zoho One domains - one.zoho.*, and one.zohocloud.ca for Canada, which is a different family however alike it looks; Zoho Analytics has neither. No content script of ours runs on one.zoho.*: it is there so the panel can tell which org a Zoho One tab belongs to. The two AI hosts are reached only if someone turns the assistant on. And nothing of ours runs on zoost.it until you press Report this problem: it opens the report page and writes the text into the box, so that you read it before anything is sent. The manifest is the authority.
How you can checkTwenty files of plain JavaScript for Zoho CRM, twelve for Zoho Analytics. No bundler, no minifier: what you read is what runs. Each release is built by GitHub twice over and signed, and one command verifies the published file.
How to judge it without meEvery command is on the nerd page, and with them a prompt you can paste into whichever assistant you use: it reads the whole repository and answers at three levels - what this is in plain language, what it can do for somebody who works in Zoho every day, and what you need if you are the one approving it. Including where the claims fail. It is short enough to read in one go, which is the point of shipping it unminified.

Details, endpoint by endpoint: the nerd page. What is stored and where it travels: the privacy policy.

Get started

  1. Try it without connecting anything. Install either extension and press + Sample. It writes a workspace of invented data into your working folder, and the tree, the diagrams, the audit and the exports all work on it - no Zoho tab, no account. Nothing reaches the platform, and you delete it by deleting the folder. What is in it.
  2. Pick the product you want to look at: Zoost - workbench for Zoho CRM or Zoost - workbench for Zoho Analytics.
  3. Install the extension from the Chrome Web Store. Both are there.
  4. Choose one working folder. Each Zoost keeps its own subfolder inside it, so a single folder serves them all and the two never meet.
  5. Open the Zoho tab you want to mirror, create the workspace and pull. Then git init, and you have a history from today onwards.
