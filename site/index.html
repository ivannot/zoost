Everything you built inside Zoho is yours.
And with Zoost you can see all of it at once.

Your Deluge code, your module schema, your workspaces and the SQL behind them - one object at a time, in a browser tab. Zoost copies all of it to plain files on your own disk, then draws you the map: what calls what, what depends on what, what nothing uses any more.

What every Zoost has in common

It only reads

No Zoost calls an endpoint that creates, edits or deletes anything in Zoho. You keep working where you already work; this is the window onto it.

Plain files, your Git

A folder you choose, filled with ordinary files. Put it under version control and git diff answers what changed last month - which neither product can answer about itself.

The whole thing at once

Search everything together, follow a name to where it is used, and hand the lot to a colleague as one document.

Numbers without a grade

You get counts and lists. A function that runs to four hundred lines may be a perfectly clean mapping table, and only you know which of yours those are, so nothing here is scored or flagged. Every figure says what it does not cover, right beside itself.

Nothing leaves the machine

No server, no account, no telemetry. The only exception is the optional AI assistant, and only if you give it your own key.

Checkable, not just claimed

GitHub builds each release from a tagged commit, twice over to prove the bytes are reproducible, and signs it. The archive on the Release is the file sent to the Store, and one command tells you whether that is true.

Free, open, and yours to fork

Apache-2.0, no build step, no dependencies. Readable by anyone about to give it access to their data - which is what you are being asked to do.

Want the detail - which endpoints, what breaks it, how a release is signed? It is all on the nerd page, which is where it belongs.

Built and maintained by one person, with substantial help from Claude - "Claudio", to me - on design, code and wording. The judgement calls, and the responsibility for the result, are mine.

If you have to approve it

Somebody has asked you whether they can install a browser extension that reads the company's Zoho CRM, or its Zoho Analytics. Six lines.

What it readsConfiguration only: code, field definitions, automations, the structure of a workspace. Never the data itself - in Zoho CRM no contacts, no deals, no notes; in Zoho Analytics never the rows inside a table.
What it writesTo Zoho, nothing. It calls no endpoint that creates, edits or deletes.
Where the data goesA folder on that person's own computer. No server, no account, no telemetry.
The one exceptionAn optional AI assistant, off until someone enters their own API key. Then, and only then, the parts it needs go to Anthropic or OpenAI. It can reach nowhere else.
What it can seeExactly what that person can already see in Zoho. It uses their session and their permissions, and can do nothing they could not do.
How you can checkThe source is about twenty readable files. Each release is built by GitHub twice over and signed, and one command verifies the file that was published.

Details, endpoint by endpoint: the nerd page. What is stored and where it travels: the privacy policy.

Get started

  1. Pick the product you want to look at: Zoost - workbench for Zoho CRM or Zoost - workbench for Zoho Analytics.
  2. Install the extension from the Chrome Web Store. Both are there.
  3. Choose one working folder. Each Zoost keeps its own subfolder inside it, so a single folder serves them all and the two never meet.
  4. Open the Zoho tab you want to mirror, create the workspace and pull. Then git init, and you have a history from today onwards.
