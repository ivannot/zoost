Zoost AnalyticsZoost - workbench for Zoho Analytics

Hundreds of views, and no way
to see the shape of them. Zoost draws you the map.

Every view with its type and dates, the columns and foreign keys of every table, and the SQL behind each query table as a file you can diff. Then the ER diagram, what reads from what - and the list of what nothing seems to read any more, with what that list cannot see written beside it.

Why it exists

A workspace outgrows its author

A few years in, a workspace is hundreds of views: tables, query tables holding SQL somebody wrote at 2am, and reports built on reports. Zoho Analytics will answer what one view depends on, one view at a time. It will not tell you the shape of the whole thing.

A history for everything you pulled

Zoho Analytics keeps no history of anything: change a query table's SQL, a column or a relation and the previous state is gone. The mirror is ordinary files. Put them under Git and git diff answers what changed in this workspace last month - the question that matters most the day a number moves and nobody knows why. Git is optional: without it the mirror is still ordinary files you can search and hand over.

The SQL is the source

Tables are schema and reports are configuration, but a query table's SQL is code somebody wrote. It lands as one .sql file each, so it can be diffed, reviewed and searched like the code it is.

Before you delete anything

Asking Zoho Analytics what depends on a view, three hundred times by hand, is how the question never gets asked. Zoost asks it once for everything - and calls the answer a candidate, because a shared link or a scheduled export is invisible to that graph.

What you built, and what Zoho put there

Half the tables in a connected workspace arrived by sync and were never yours. Zoho Analytics' own ER model knows which, and the view list marks them - so the inventory is of your work, not of everything.

Several workspaces, side by side

One working folder, a subfolder per workspace, each one bound to the workspace it came from. If you consult, four clients stay mirrored at once, and the panel takes the workspace from the tab you are on: which client you are looking at is answered by the browser, not by remembering.

What's inside

Every view, in one list

  • Type, folder, owner, column count and dates - sortable, and searchable inside the column names, so you can find which table carries a field.
  • When the design last changed and when the data last refreshed, kept apart: they are different facts.
  • Tables Zoho put there by sync are marked, so the inventory is of your work.

Structure, even for reports

  • Columns and Zoho data types for every table and query table.
  • A report has no columns of its own, so Zoost follows what it is built on and shows that structure - saying whose it is.
  • Foreign keys on every column, both ways: what it points at, and what points at it. Each one is a link.

The SQL, as files

  • One .sql per query table - the only thing here somebody actually wrote, and the part git diff can answer about.
  • From any view, Open in Zoho ↗: the panel builds the address of that view and takes you there. It reads Zoho, it does not drive it.
  • Search across every query at once, from the panel: the in: SQL switch beside the search box looks inside all of them and shows the matching line. They are files on your disk as well, so grep and your editor answer the same question.
  • Each records the tables it reads and which of their columns it touches, so if I drop this column, what breaks has an answer.

An ER diagram that stays readable

  • Tables as boxes, relations as arrows, the join written exactly as Zoho writes it.
  • Focus one table and walk out from it; click an arc to isolate a single relation.
  • Spacing and label size are live sliders. Save as PDF for a wall-size print.

What nothing depends on

  • Zoho Analytics' own dependency answer, asked once for everything instead of one view at a time.
  • For any view: what it reads, what reads it, and the dashboards it appears on.
  • Candidates, never a verdict - a shared link or a scheduled export is invisible to that graph, and the number says so.

Exports, and an optional assistant

  • The whole workspace as one HTML file, or as Markdown - which carries the constraints of Zoho Analytics' SQL dialect, so an assistant does not write queries that cannot run.
  • A dialog decides what may leave your machine, section by section.
  • With your own key, an assistant that explores your workspace - and never your rows, because Zoost does not read them.
  • When the assistant is worth a key, and when the export is the better route.

What it does not do

It calls no write endpoint

No creating, editing or deleting a view. One endpoint it calls is a POST whose URL contains CREATE - ZDBCreateERD.ma, the call that returns the workspace's ER model, and the one Zoho Analytics' own diagram screen makes. What leaves here is that one request; what a server keeps afterwards is not something an extension can prove, and the nerd page says so rather than glossing it.

It never reads your rows

Structure, relations, SQL and metadata only. The endpoints that return cell values exist, and are deliberately not called - which is also why the AI assistant can never tell you what is in the data.

Report definitions are not covered

Which columns a chart puts on which axis, and how it aggregates them, would come welded to the computed series - your data. So that endpoint stays unused and this gap stays stated.

It does not validate SQL

Zoost never runs, checks or deploys a query. What the assistant writes is a draft; Zoho Analytics is the only thing that can tell you it compiles.

Relations are Zoho Analytics' own

The foreign keys come from the ER model Zoho Analytics itself draws. What that model does not draw, Zoost does not know - and does not invent.

Get started

  1. Install it from the Chrome Web Store.
  2. Set a working folder - the same one your other Zoost uses, if you have one. Each product keeps its own subfolder inside it.
  3. Open a workspace in Zoho Analytics. The panel takes the workspace from the tab you are on; there is nothing to configure and nothing to pick wrong.
  4. Press + Workspace, then Pull all. A few hundred views take under a minute.
  5. Optional: git init in the workspace folder, and from today you have a history. Everything else works without it.

Or press + Sample and skip all of it. It writes a workspace of invented data into the working folder, so you can open the view census, the ER diagram and the exports before pointing Zoost at anything of your own. No Zoho tab, no account.

It is generated rather than fetched, everything that would talk to Zoho is disabled for it, and you delete it like any other workspace. What that is worth, and how to evaluate it that way →

What it rests on, the two endpoints it deliberately never calls, and how to check any of it: the nerd page.

Everything runs in your browser, using the Zoho session you are already signed into. No server, no account, no telemetry. The only thing that ever leaves your machine is what you choose to send to an AI provider, and never the rows in your tables.
