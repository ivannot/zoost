AI and Zoost

The workbench is complete without an AI model, and that is how most people will use it. This page explains what an assistant can do with the files Zoost already writes, what the built-in assistant adds, and when an API key is not worth using.

Zoost works without AI

Zoost copies what you built inside Zoho CRM or Zoho Analytics to plain files on your own machine. From those files it creates what the platform does not provide: a complete inventory, diagrams you can explore and print, full-text search, an audit of items with no known references, and two export formats.

None of that involves a model, a key or an account. If you never open the assistant, nothing is missing - it was added to a workbench that already worked. I am saying this first rather than last because a tool that only makes sense once you have bought an API key is a different product, and I did not want to build that one.

Two exports, two readers

Both exports are written from the same mirror and carry the same facts. What differs is who is meant to read them.

HTML - for people

A single self-contained file with a table of contents, sections and tables. Hand it to a colleague, to an auditor, to a client, to the consultant taking the account over. It opens in any browser, it prints, and the person reading it needs nothing installed and no access to your org.

Markdown - for a model

The same content in a format that is easy for a language model to interpret: headings, tables and code blocks, without visual elements to decode. Attach this file to a chat.

Before either is written, a dialog asks what may go into it - functions, module schema, layout detail, relations, workflows, schedules, actions, connections, failures, sender addresses, health - with the Deluge source code as a separate, clearly marked choice, because it is the sensitive part. There are two presets, Everything and Share-safe, and the choice is remembered. A section whose data is older than the rest arrives unticked, with the date and the reason.

An export is intended to leave your machine. That is why one dialog shows every available section and lets you decide exactly what to include before the file is created.

Use an assistant you already have

Take the Markdown file to whichever assistant you already use - Claude, ChatGPT, Gemini, Copilot - and ask your question there. In the browser or in its desktop or mobile app - it is a file either way. No key, no configuration, nothing switched on inside Zoost.

This is often all you need, and it is important to say so clearly. The sample org that ships with Zoost - the 305 files itemised on Try it, Deluge sources included - is about 200 KB of text, which a current model can usually handle in one go.

So if the question is "explain what this function does" or "summarise these workflows for the handover note", this route gives you a larger model, a proper chat window and a conversation you can keep.

It has one structural limit, and it decides everything below. The export is a snapshot with a scope chosen in advance. Whatever you left out is invisible to the model in a way it has no way to detect - so it answers anyway, in the same confident register, about an org it has seen part of.

What the built-in assistant adds

The assistant inside the panel does not receive the entire org. It receives a vocabulary containing the names of the available objects and a set of tools that read the mirror on your disk. It uses those tools to retrieve only the details needed for your question.

list_functions get_function who_calls get_callees search_code get_module get_workflow list_workflows get_connection list_actions list_failures

Zoost - workbench for Zoho Analytics

list_views get_view get_structure get_sql search_sql search_columns get_relations who_uses orphans

Every tool call appears in the chat as it happens, so you can see what the assistant read. This creates four practical differences.

Scale. The entire org does not need to be sent. What travels with each message is the index of names, capped at 72,000 characters by default and adjustable. Under the chat title the panel prints the real size of the workspace you have open, in characters and approximate tokens.

When an org is too large to name in full, what gets dropped is decided rather than arbitrary. The function list is never dropped - in Zoho Analytics, the data objects - because it is the vocabulary everything else refers to. Whatever is left out is stated as left out, so the model cannot conclude that something does not exist just because it was not shown it.

It knows what you are looking at. Select a function, a workflow, a query table, and ask "what does this do?" with no preamble. The selection is part of the prompt.

Freshness. There is no snapshot to redo after the next pull.

It is available where the question arises. This is often the most useful difference. Someone with a question is unlikely to prepare an export, open another chat and explain the context. They are more likely to open a tab or ask a colleague. Keeping the assistant in the panel removes that extra work.

When it is worth a key

Here is the honest version, which is narrower than the way this kind of feature usually gets described.

Your situationWhat I would do
A few hundred objects, a question now and thenExport Markdown, paste it into the assistant you already pay for
One item in front of you, one questionEither. The export is cheaper and the chat window is bigger
The org is large enough that you would have to think about whether it fitsThe built-in assistant, which retrieves instead of being handed everything
"What breaks if I change this?", traced across the whole orgThe built-in assistant with Anthropic, which can follow the trail by itself
The person asking is not the person who could build an exportThe built-in assistant. This is the case it was written for
You would rather nothing left the machine without you watchingThe export - and read the file before you paste it

The useful claim is more precise than "it has AI": the built-in assistant provides targeted retrieval and immediate access, not additional knowledge. The export and the assistant read the same mirror and can reach the same facts. The difference is how they retrieve those facts and where you ask the question.

Why your own key

Because there is no Zoost server. The request goes from your browser straight to Anthropic or OpenAI, carrying your key and billed to your account. Nothing passes through me, and there is nothing of mine for it to pass through: no backend, no account, no log.

What an API key is, since the rest of this page assumes it

Anthropic and OpenAI sell two different things. One is the chat you already talk to - Claude, ChatGPT, Gemini - in a browser or in its own app, paid by the month and used by typing into it. The other is the same models reached by a program rather than by a person.

For that second one you ask their developer console for a key: a long string of characters you paste into the program. From then on the program can send questions, billed to you by the amount of text sent and received rather than by the month.

A key is a credential, not a setting. Anyone holding it can spend on your account, which is why it is worth a passphrase and a spending limit, and why nobody should ever have yours - including me. A Claude.ai or ChatGPT Plus subscription is neither one of these nor does it include one; that catches most people out, and it is the reason the steps below say it twice.

The alternative is the common one: the extension talks to a service the author runs, which holds a key and relays the questions. More convenient, and a subscription. It also means the structure of your org crossing a machine you do not control. Given the rest of this product, that was not a trade I could make and still say the rest of it with a straight face.

One consequence you can see in the source: the call to Anthropic carries the header anthropic-dangerous-direct-browser-access: true. The name is Anthropic's own and it is a fair warning - it means there is no server in the middle, which is precisely the property being chosen here. The price of it is that the key lives in your browser profile, which is why the passphrase below exists.

Getting a key

Two providers, because those two are tested and they are the only two either manifest is allowed to reach. Others could be added; until one has actually been tried against a real workspace it will not be, and an untested feature is worse than a missing one.

Anthropic (Claude) - the agent engine

  1. Open console.anthropic.com, sign in, and create an API key.
  2. A Claude.ai subscription is not an API key. The developer API is a separate product, billed on prepaid credit.
  3. Set a spending limit while you are in the console. It is the only limit here that does not depend on estimating anything.
  4. In Zoost, open Settings and paste the key with the model id written exactly as Anthropic writes it.

With this engine the assistant runs as an agent: it opens what it needs, follows callers, searches the code, and comes back with an answer plus the trail it took. Max tool steps caps how many times it may reach for a tool before it has to answer - 20 by default, and most answers use two or three.

OpenAI (ChatGPT) - single pass

  1. Open platform.openai.com/api-keys and choose Create new secret key. Copy it immediately - it is shown once.
  2. ChatGPT Plus is not API access. Add prepaid credit under Billing, and set a monthly limit while you are there.
  3. Paste the key and the model id into Settings.

This engine receives the index and whatever you have open, and answers in one pass. It cannot go and read a second function by itself, so it asks you for what it is missing instead of inventing it. That is the intended behaviour and it is also a real difference in capability - the engine in use is shown as a badge in the chat header, so you always know which one you are talking to.

What it costs

I am not going to print prices: they are the providers' and they move. What decides yours is the index, which travels with every message and whose size the panel shows you, plus however many tool steps an answer takes. Tool answers are capped and say how to narrow the question rather than returning nine hundred lines. Set the spending limit; that part is not an estimate.

There is a third term, and people miss it because the control that governs it looks like housekeeping. The whole conversation is re-sent with every message - your questions, the answers, and every function, view or SQL file the agent opened along the way. Nothing trims it. The tenth question in a thread costs more than the first, over material that has nothing to do with it.

Clear is what governs that. It is not housekeeping: it is your control over how much history you are paying to carry. Clear it when you change subject and you buy two things at once - a cheaper call, and a sharper answer, because the model is no longer reading around a previous investigation to reach your question. Changing workspace clears it too, for a different reason: the old thread was about another org.

Protecting the key

By default the key is stored in clear text in your browser profile. Chrome gives an extension no credential store and no encryption at rest, so encrypting it with a key kept beside the ciphertext would be theatre - and worse than storing it plainly, because it would let me claim a protection I do not provide.

What is offered instead is a passphrase only you hold. The key is encrypted with it and you type it once per browser session. There is no recovery - no hint, no reset, no escrow. Lose it, and each provider's Forget button clears that key so you can paste a new one; Remove the protection takes the whole thing off in one control.

It is off by default, and stated rather than defaulted. On a personal machine a passphrase each session buys little; on a shared one it buys a lot. Nobody but you can price that.

What it will not do

  • It does not write to Zoho. Every tool reads the mirror on your disk. There is no write path in either extension, for the AI or for anything else.
  • It does not see your records. The mirror holds structure, definitions and code - field names, not field values. Zoost does not download customer data, so there is none for a model to be given.
  • It does not carry a conversation between workspaces. Change workspace and the thread is dropped, because a reply naming the previous org's functions sitting above a question about a new one is worse than starting again.
  • What it writes is a draft. Zoost never runs, validates or deploys anything - including the SQL the Zoho Analytics assistant will happily write for you.
  • Nothing else here needs it. Turn it off, never configure it, and the workbench is the same workbench. That is the intended shape rather than a fallback.

The operational detail - where the settings live, what the badge means, what happens when the folder permission lapses - is in the guides: Zoost CRM and Zoost Analytics. What the extensions store and where it travels is set out in the privacy policy.
