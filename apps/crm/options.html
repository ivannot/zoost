Working folder

One folder holds every workspace. Zoost creates a subfolder per Zoho org, named instance[-sandbox]-orgid. The folder name is only a label - a workspace is identified by the org id inside its .zoost.json, so renaming is safe.

Not set
Zoost will hold read and write access to everything inside that folder, for as long as the browser keeps the permission. A dedicated folder is strongly recommended - not your home or Documents.

Chrome may ask the side panel to confirm this permission again the first time it writes. That prompt is expected and appears once per session at most.

Data centre

Where your Zoho CRM account lives. It is the starting point for Go to Zoho CRM on the screen shown when there is no Zoho CRM tab - that screen carries a picklist of every data centre, because after signing out of one org which one you want next is a choice, not something to deduce from the one you happen to have open. The picklist starts on the workspace's or the tab's data centre when there is one, and on this default when there is not. The list is the manifest's own: a host the extension cannot reach is not one it offers.

AI assistant

Bring your own key. Two providers are supported: Anthropic and OpenAI. Requests go straight from your browser to the one you choose - never through any server of ours. Keys are stored in chrome.storage.local on this machine.

OpenAI (ChatGPT)

Characters. The assistant is given an index of the org with every message, so this is what a question costs before you have asked anything - roughly one token per four characters. The panel shows the real figure for the workspace you have open, under the chat title.

When an org does not fit, the order is decided rather than arbitrary: the function list is never dropped - it is the vocabulary everything else refers to - and module and connection names go first, because the assistant can still fetch those by name with its tools. Whatever is left out is named as left out, in the index itself, so an absence in it is never presented as an absence in the org.

How many times the assistant may reach for a tool before it has to answer. 20 is the default. Raise it for questions that span the whole org; lower it to cap what a single question can cost. It is a ceiling, not a target - most answers use two or three.

Tokens one answer may cost. 16384 is the default. A model that reasons before answering spends this on the reasoning too, and if it runs out there the reply arrives empty - the panel says so and names this box. Raise it for questions that need a long answer; it is a ceiling, and you are billed for what is used, not for what is allowed.

Lost the passphrase?

Off by default, and that is a real choice rather than a lapse. Chrome gives extensions no encryption at rest and no credential store, so anything the extension can unlock on its own, anyone with your browser profile can unlock too - encrypting with a key kept beside it would be theatre. The only real protection is a secret we do not hold. On your own laptop that buys little and costs a passphrase every time the browser restarts; on a shared or managed machine it buys a lot. Nobody but you can price that. There is no recovery. Forget it and you paste the API key again and choose again - which costs one visit to your provider's dashboard, and is the honest shape for a secret that cheap to replace. And what it does not do: while the key is unlocked it sits in the browser's memory, where the browser can read it. A passphrase protects the key at rest - a copied profile, a backup, someone else on this machine - not a key already unlocked in a running browser.

The assistant sends the parts of your workspace it needs - including Deluge source code - to the provider you configure. Check that this is acceptable for your organisation before use.

Tabs

Which types the side panel offers, and in what order. A tab you turn off is absent, not greyed out - the panel is 400px wide and a control that does nothing is just noise. Nothing is deleted by hiding a tab: Pull all still mirrors that type, and it still appears in exports and in what the AI can see - unless you also clear its pull box, which is the separate question of whether Zoost should ask Zoho for that type at all. Turning a tab off clears it for you, because most tabs are turned off for an area the account cannot read and pulling it then only produces an error. Turn it back on if you mirror a type for Git without browsing it.

Export defaults

What the export dialog starts with. You can still change it per export.

Saved search patterns

Named regular expressions, offered by the ▾ menu beside the panel's search box when the full-text search is on. JavaScript syntax, case-insensitive, ^ and $ match at each line. The two starters - an email address, and the 18-digit numeric id Zoho gives every record - can be edited or removed like anything you add, and Restore the starters puts back whichever is missing without touching the rest.

Diagram layout

The ER diagram reads these values when it opens. They are the same setting the graph window's Layout panel edits, so adjusting a slider there updates what you see here - there is no separate default to fall out of sync. Reset to preset in the graph returns to the built-in values for the current emphasis mode, not to these.

How much it will draw at once

The diagram refuses past this many boxes, and the count beside its tab says how many the current filters leave. 800 is the default because a real org reported 725 boxes and 400 would have refused it: 200 boxes lay out in about 0.5 seconds, 400 in 1.3, 600 in 2.2, 1000 in 4.9 and 1200 in about 7, and those figures are the layout alone - drawing the boxes is on top of them. Raise it if you would rather wait: nothing here stops you, and nothing pretends the result improves. Past 80 boxes start covering each other whatever this is set to, which is why the count turns amber there and why a raised ceiling buys you more of the graph rather than a better picture of it.
