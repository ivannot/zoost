The version before this one on the Chrome Web Store was 1.27.0, so this note covers everything since
it: a search that takes a pattern, a way to tell me when something breaks, and a release about one
promise - a pull either completes, or the panel says so.

## The search box takes a pattern

Beside **in: SQL** there is a new **.\*** toggle. With it on, what you type is read as a regular
expression instead of as literal text - `^SELECT.*JOIN`, `\bdate_add\b`, `WHERE\s+\w+\s+IS NULL` -
across every query in the workspace. A pattern that does not parse says so and searches nothing,
rather than answering «no matches» about a search that never ran.

Patterns you use often can be **saved with a name**. The list is in the menu beside the toggle: pick
one and it goes into the box; type a new one and the menu offers to save it under a name. Two are
there to begin with - an email address, and a Zoho id - and the whole list is editable in **Settings**,
where you can rename, change or empty it. Emptying it keeps it empty: the starters do not come back
behind you, and there is a button to put them back when you want them.

Matches are painted in the query you open, not only counted in the list - so the line the search found
is visible in the detail without hunting for it.

## When something breaks, you can tell me - and you decide what leaves

The status line now offers **Report this problem** when something has failed. It builds a report -
versions, the error, the last few status lines, counters - opens
[zoost.it/report](https://zoost.it/report) in its own window and writes the text **into the page**,
where you read it in full before anything is sent. You can unlock it and cut whatever you want; if you
do, the report says so, so nobody reads an edited trace as evidence. Nothing is sent until you press
Send, and nothing is sent automatically, ever.

What it carries is decided by a fixed list of fields, never by a sweep of what happens to be in
memory: no SQL, no source, no keys, and no file of yours is read to build it. Names, paths, ids,
addresses and hosts are stripped where they are recognised - which is exactly why you are shown the
result instead of being told to trust it.

The row that offers it can now be dismissed with **✕**. It could not before: every other status line
is replaced by the next one, and after a report there is no next one, so it stayed for the rest of the
session.

## A pull is now all-or-nothing

**Pull all** builds the whole snapshot first and publishes it in one move - views, schema, SQL and
lineage together. If a stage fails, the panel keeps showing the previous complete picture instead
of a mixture of old and new. On disk, a marker records when a pull is mid-write: a mirror whose
last pull was interrupted is refused with a clear message ("run Pull all to repair") rather than
presented as if its files described one moment.

## "Not read" stopped masquerading as "does not exist"

A query table whose SQL could not be fetched simply vanished from every surface: the assistant
called it "not a query table", searches said "no matches" over queries they never opened, and the
exports skipped it without a trace. Every surface now tells the two apart - the detail pane, the
full-text search (which states its coverage: "searched 47/50 - absence is not exhaustive"), the
assistant's answers, and both exports, where the query keeps its heading with the reason and the
remedy under it.

## Two assistant tools now actually work

`search_sql` and `search_columns` had never run once: asked anything, they answered "View not
found". Both work now, and every declared tool is exercised by a test so this cannot happen
silently again. `get_relations` by name is also fixed.

## Old SQL files are cleaned up

A query table you delete or rename in Zoho Analytics no longer leaves its old .sql file in the
workspace folder forever. The pull removes what its own index no longer names, and a removal that
fails is said and retried by the next pull.

## One workspace at a time, enforced

While a pull is writing, switching workspace is refused - and everything long-running (the diagram,
the exports, the assistant) checks it still belongs to the workspace on screen before showing or
writing anything.

## Also fixed

- A CSRF token whose value contained an `=` was cut short before being sent, which came back from Zoho
  as a failure that looked like an expired session. Not seen in the wild, and now impossible.
- The saved-pattern list refuses two patterns with the same name and refuses to save the same pattern
  twice, so the menu can always tell its entries apart.
- The last stage of a pull is disk, and it was the one stage that said nothing: after «Reading
  lineage... 50 / 50» the panel wrote three files, one .sql per query table and a cleanup without a
  word, which on a real workspace takes long enough to read as a hang. It now says what it is writing
  and counts the SQL files.
- «Create workspace for ...» - the button the panel offers when your tab and your workspace disagree -
  refused to do it, saying that nothing reads Zoho Analytics until the two match. It was the guard on
  the mismatch refusing the one action whose purpose is to end it. And once created, the panel went
  back to the workspace you were in instead of the one it had just made.
- A workspace is called what you called it. When your tab and your folder disagree, the bar named the
  platform's workspace - «Default Workspace» - over a folder you had named yourself, in the one
  sentence written to be recognised. The name you gave it comes first now, in the sentence and on both
  buttons, with the workspace id beside it.
- A workspace Zoho Analytics gives no readable name to is said to have none, beside the ✎ that names
  it, instead of appearing in the list as a bare id.
- The diagram window owns its drawing: two windows opened close together can no longer swap
  payloads, and the copy is removed the moment the window reads it.
- A saved API key is derived at 600,000 PBKDF2 iterations (the current OWASP figure). Keys saved
  earlier keep working unchanged and are upgraded the next time you lock them.
- A markdown link in an assistant reply can no longer break out of its own attribute, and names
  from your workspace shown in the diagram status line are escaped.
