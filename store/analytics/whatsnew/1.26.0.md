**The relationship diagram was rebuilt to work on a real workspace.** It used to draw a small
picture in the middle of a large empty window and then give up quietly on anything big: at a few
hundred tables it left hundreds of boxes covering each other and said nothing about it. The layout
now sizes itself to what it is actually drawing, so a focused diagram fills the window instead of
sitting in the middle of it, and the pass that keeps boxes apart was made to work hardest exactly
where there are most boxes to separate - which is the opposite of what it did before.

**How much it will draw is a setting, and the number beside the tab tells you where you stand.**
The ceiling is **800** tables by default, because a real workspace came in at 725 and 400 would have
refused it, and you can raise it in Settings - which states what raising it buys you (more of the
graph, not a better picture of it) and what each size costs in seconds. Past **80** tables the count
turns amber and warns you the drawing will be crowded, and then draws it anyway. That is your call
to make, not ours.

**The whole-workspace view is reachable again.** A readability limit had been written as a wall, and
a workspace with more than eighty tables in one category could never get under it by any combination
of filters - so the limit did not make the whole view worse, it removed it. Reported, and right.

**Arrange the diagram yourself, and it stays arranged.** Drag a table where it belongs: the automatic
layout is a starting point, and past eighty boxes it crowds whatever it does - you are the one who
knows which two tables have to sit side by side. A table you drag rises above the others and stays
there, the arcs are redrawn where you drop it, and the drop tells you how many boxes it now covers.
Change a filter and what you moved keeps its place; only the tables that are new to the drawing are
placed for you, and they make room **around** what you built rather than pushing it aside. Two
tables you overlapped yourself stay overlapped, because you put them there. **Re-layout** throws the
whole arrangement away when you want to start over, and what you arranged is what **Save PDF**
prints.

**Keep the arrangement you made.** Everything under the new **File** button in the diagram's toolbar:
**Save PDF** as before, and now **Save arrangement** and **Load arrangement**. An arrangement is a
plain file you name yourself, so the same diagram can have several readings - one arranged for a
presentation, one for chasing a problem through the joins - and you can hand one to a colleague or
keep it beside the mirror. Nothing is restored automatically and there is no list of saved
arrangements to manage: they are files, in your folders, under your names.

Load one onto a workspace the mirror has moved on and **the diagram of today wins, with every loss
counted**: a table that is gone drops its position, a table that is new is placed by the layout
around what you kept, and a table that was renamed loses its position rather than inheriting a
stranger's - a box sitting where a different one used to sit would misstate the shape you built. The
status line says what happened in numbers, and if every table still matches while the relations have
changed, it says that too, because that is the drift nothing else would show. An arrangement from
another workspace is refused by name rather than reported as an empty result.

**Take a branch off the drawing.** Where an arc meets a table there is now a mark that removes the
table at the other end, together with everything that can no longer be reached without it - so
anything reachable another way stays. Before you press, the tooltip names what will go and counts
it, each name in the colour its box wears, and the ones currently on screen are outlined at the same
moment: at the zoom these are read at, most of what a cascade takes is off screen. A **+** in the
same place brings it all back. It hides rather than laying the diagram out again, so it composes
with an arrangement instead of destroying it.

**Getting around it.** Double-click empty canvas to zoom in on that point, which ends up in the
middle of the window; **Fit** is the way back, and a window resize re-frames the drawing for you
unless you have moved the view yourself. Dragging the sheet to pan no longer leaves every label it
passed over highlighted.

**When a read from Zoho fails, the panel now says a fix may already be released** - beside the
status line, where you are actually looking when something breaks, rather than only on the website.

**A query table no longer looks like a table.** The relationship diagram coloured every box the same
blue: the rule it used asks for the two namespaces the Zoho CRM has, which a workspace whose views
are tables and query tables never matches. Boxes now wear the colour their kind wears on the filter
chips above them, so the diagram and the chips can no longer say different things.

**Fit frames the drawing rather than its distance from the corner.** It resized and did not centre,
which was invisible until you arranged something: a table dragged to the left left the drawing
against one edge with all the empty space on the other. The printed page had the same defect.

**A workspace that cannot be read says so.** It used to say "Nothing pulled yet" - so a folder that
had moved, or a drive that had gone offline, sent you to pull a workspace that was already on disk,
which changed nothing. The panel now names the file it could not read and what the browser called
the failure.

**Also:** switching a category off used to change the chip and leave the diagram exactly as it was,
so the control was lying about itself; the Settings page still showed a slider that had been retired
two versions earlier; the message shown when the diagram refuses to draw quoted the wrong default
ceiling; folding a branch no longer lets the frame keep sizing itself for boxes nobody can see; arcs
arriving at the same side of a box now land apart instead of converging on one point, and a box
grows when it needs the room for them; and the toolbar icon is drawn at the size Chrome asks for
rather than scaled down from a larger one.
