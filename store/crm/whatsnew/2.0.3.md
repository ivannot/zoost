# Zoost CRM 2.0.3

One defect, reported on a real org with a picture of it: the workspace list had the same workspaces
in it several times over.

**Every click during one permission prompt is one grant, and one list.** Chrome drops the working
folder's permission between sessions, and a click anywhere in the panel asks for it back. The prompt
is Chrome's own dialog, placed where Chrome likes - and on a detached window like Zoost's it can open
*behind* the panel, where you cannot see it. The panel then looks frozen, so you click again; each of
those clicks started its own request, they all waited on the same invisible dialog, and when it was
finally answered they all woke up and each one reloaded the workspace list on top of the last. Four
clicks, four copies of every workspace. The request is shared now - the first click asks, the rest
wait on that same answer, and only one of them reloads - and the list is rebuilt rather than appended
to, so even a reload that arrives late cannot double it.

**And the panel says when it is waiting on that dialog.** If a grant has not been answered after a
moment, the status line reads «Chrome is asking about the working folder - if you cannot see the
dialog, look behind this window». Nothing in a page can see that prompt, let alone move it; what the
panel does know is that it has asked and has not been answered, and saying so is what stops the
clicking. A prompt answered straight away - the ordinary case - still says nothing. The guide carries
the same warning.
