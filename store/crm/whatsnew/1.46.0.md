The version before this one on the Chrome Web Store was 1.44.0, so this note covers everything since
it: two headline additions - a search that takes a pattern, and a way to tell me when something breaks -
on top of a release about one promise, that what you see is your org and never a mixture of two.

## The search box takes a pattern

Beside **in: code** there is a new **.\*** toggle. With it on, what you type is read as a regular
expression instead of as literal text - `invokeurl.*POST`, `\bzoho\.crm\.updateRecord\b`,
`catch\s*\(` - across every function source in the workspace. A pattern that does not parse says so
and searches nothing, rather than answering «no matches» about a search that never ran.

Patterns you use often can be **saved with a name**. The list is in the menu beside the toggle: pick
one and it goes into the box; type a new one and the menu offers to save it under a name. Two are
there to begin with - an email address, and a Zoho id - and the whole list is editable in **Settings**,
where you can rename, change or empty it. Emptying it keeps it empty: the starters do not come back
behind you, and there is a button to put them back when you want them.

A result now opens **at the line that matched** instead of at the top of the function, and every match
is painted in the source while the search is active.

## When something breaks, you can tell me - and you decide what leaves

The status line now offers **Report this problem** when something has failed. It builds a report -
versions, the error, the last few status lines, counters - opens
[zoost.it/report](https://zoost.it/report) in its own window and writes the text **into the page**,
where you read it in full before anything is sent. You can unlock it and cut whatever you want; if you
do, the report says so, so nobody reads an edited trace as evidence. Nothing is sent until you press
Send, and nothing is sent automatically, ever.

What it carries is decided by a fixed list of fields, never by a sweep of what happens to be in
memory: no Deluge source, no keys, and no file of yours is read to build it. Names, paths, ids,
addresses and hosts are stripped where they are recognised - which is exactly why you are shown the
result instead of being told to trust it.

The row that offers it can now be dismissed with **✕**. It could not before: every other status line
is replaced by the next one, and after a report there is no next one, so it stayed for the rest of the
session.

## The related lists have a tab of their own

A module's detail was two tabs, and its related lists sat at the bottom of **Details** - under the
refusal banner, the names and the layout counts. In a side panel that is a column you scroll blind.
They are now **Fields · Related lists · Details**, and the API name that `zoho.crm.getRelatedRecords()`
needs is the first thing on the middle tab. Click one to copy it, as before.

**Details** now reads in the order the questions come in: what the module *is* - display name, api_name,
the generated name, its layouts - and then what your Deluge does with it, «read by» and «written by».
The whole pane scrolls as one, instead of a box of names with a scrollbar of its own inside a pane
with another.

## One workspace at a time, enforced

While a pull is writing a workspace, switching to another one is refused - the list greys out and
the panel says "Pull in progress". Before this, changing workspace mid-pull could put one org's
files into another org's folder, or leave the panel showing a mixture of the two. The same
guarantee now covers everything long-running: the diagrams, the health audit, the exports and the
assistant all check that the workspace they started in is still the one on screen before they show
or write anything - and stop silently if it is not.

## Pull all now sees what changed in Zoho

The function list Zoho returns carries a modified timestamp, and the panel now compares it against
what is on disk - so a function edited by a colleague, or while the panel was closed, is
re-downloaded by the next **Pull all** instead of silently keeping its old source. A renamed
function is fetched at its new path and its old files are cleaned up, instead of lingering forever.

## The assistant and the reports stopped inventing zeros

A connection whose usage could not be measured used to show "used by 0 functions"; a module list
that failed to write still reported "complete"; an export could say "Functions: 0" when the graph
failed to build. All of these now say what actually happened - "could not be read", with the reason -
because an unknown shown as a zero is the one thing a mirror must never do. The failures list also
says when Zoho's answer was cut at its first page.

## Live sync got sharper

A function you save, create or delete in the Zoho editor is reflected in the panel as it happens.
This release fixes the case where a deletion showed nothing, and the one where a second save could
be missed after the extension was updated under an open tab.

## Each diagram window owns its drawing

Two diagram windows opened close together could swap payloads. Each window now receives its own
copy, consumes it on open, and the copy is removed immediately if the window cannot open at all.
The privacy page describes exactly this.

## Also fixed

- A full-text search left «Reading sources 150/150…» on screen with the spinner turning, over a search
  that had finished. The line that opens now closes.
- Switching tab left the **Refresh N outdated** button standing over a list it says nothing about.
- A CSRF token whose value contained an `=` was cut short before being sent, which came back from Zoho
  as a failure that looked like an expired session. Not seen in the wild, and now impossible.
- A stale function file that could not be removed during a pull no longer hides behind the pull's own
  success: it is counted, reported, and retried by **↻ Refresh**.
- A pull that had finished one area looked stuck while it started the next: the panel kept the
  previous line - «All 900 functions downloaded.» - through the three or four steps every area takes
  before it can say anything. Each area is now named as it starts, with its position in the run, and
  the rebuild at the end says it is rebuilding.
- After a *first* Pull all the summary index on disk described none of the functions just downloaded,
  so the next open re-derived it by walking the folder: the right answer, and on a large org the slow
  way round, with nothing saying so. It is written when the downloads finish.
- Turning off in Settings the tab you were looking at left it on screen: the panel keeps a segment for
  the tab you are standing on, which is right when a link has just taken you there and wrong when you
  have just asked for it to go. Two tabs turned off left one gone and one still there, and which was
  which depended on where you were standing.
- A hidden tab could be reached anyway: the functions that use a module, the ones on a connection, a
  workflow's function, a health row - every one of those was still a live link into a tab you had put
  away, and following one brought the tab back. They are plain text now - not an underlined word that
  does nothing, but a name that is plainly not a link - with the reason on them, and the tab stays
  where you put it.
- The per-tab filter (Kind, Type, Status) survives a data reload instead of snapping back to All.
- The Find text and the ✕ that clears it belong to the tab you typed them in.
- Clicking a row no longer scrolls the list; the row you opened stays put under your pointer.
- A saved API key is derived at 600,000 PBKDF2 iterations (the current OWASP figure). Keys saved
  earlier keep working unchanged and are upgraded the next time you lock them.
- A markdown link in an assistant reply can no longer break out of its own attribute.
- Names from your org shown in the diagram status line are escaped.
