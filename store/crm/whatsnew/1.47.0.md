**Functions Zoho compiles in another language are in the list now.** Zoho has begun serving functions
written in Node, Java and Python alongside Deluge, and Zoost could not see them at all: an org that
had them got a workspace that did not name them and did not say so. They are listed with their
language beside the name, and each one says plainly what is true of it - Zoost has the name and does
not read that kind of code. Nothing pretends they are waiting to download, nothing offers to fetch
them, and the audit no longer calls a schedule that runs one "broken wiring". The assistant knows they
exist and says so rather than answering that the function is not there.

**Connections stopped failing.** Zoho changed how that call is authorised, and every Connections pull
came back `400 - INVALID_CSRF_TOKEN`. The token is now read where Zoho's own page reads it, and a
refusal on any area recovers once and says what was actually sent if it still fails.

**"Functions in Zoho" writes nothing into Zoho.** It used to type the function's name into their
search box - the one thing Zoost ever wrote into your Zoho CRM. Zoho gave that page an address, so the
panel navigates to it and lets their page decide what to show. Nothing is written into Zoho anywhere
now: every request the extension sends it is a read.

**Zoho One and Zoho CRM Plus.** If you reach your Zoho CRM through `one.zoho.<dc>` or `crmplus.zoho.<dc>`,
Zoost now works there. Those addresses put Zoho CRM inside a frame, and the panel had no way to find
it - it opened and did nothing, with no explanation. It locates Zoho CRM by asking each frame and
keeping the one that answers, so a suite shell, a sandbox and a plain Zoho CRM all behave the same.
Nine data centres, plus the ones already covered. **"Open in Zoho"** goes to the right place inside a
suite, instead of moving the whole tab.

**The Markdown export carries everything the HTML one does.** It was missing three chapters - the
workflows with their triggers, criteria and actions, the schedules, and the health audit - which
mattered most in the file written to be given to an assistant, where an absence is invisible. Both
reports now name the same chapters, and a chapter you leave out says it was left out instead of
reporting that your org has none.

**The HTML report is a document you can navigate.** It shares its frame with the Zoho Analytics one -
a heading band that stays with you, a filter box, a table of contents - and every name in it that has
a section is a link to it: the functions under a connection, the functions Zoho reports as failing,
and the modules a function reads or writes. Two functions with the same name in different namespaces
no longer share one section and one set of cross-references.

**A module Zoho refuses to describe keeps what was captured before.** When your role loses access to
a module, or an admin hides it, the pull used to write an empty shell over its fields, lookups,
layouts and related lists - and end green. The refusal is recorded and everything else is kept.

**Empty states say the one thing that is in the way.** A stored folder loses its permission between
sessions; the panel now says so, and a click anywhere in it restores the folder rather than sending
you round the whole setup again.

**The assistant** no longer answers with an empty message when the model spends its whole budget
thinking, says when a reply was cut short instead of presenting half an answer as a whole one, and a
webhook's address is reduced to its host before anything is sent - a posting URL can carry the whole
credential in its path.

Plus a long list of smaller corrections across the panel, the diagrams, the health audit and both
reports - most of them found by driving the product rather than reading it.
