## Custom buttons

Zoost now reads the custom buttons on every module, and shows them on a Buttons tab beside Fields,
Related lists and Pipelines: what each button runs, where it appears, which layouts carry it, and how
many profiles can see it. The profile list opens in a dialog, the way a lookup's values do.

This closes a relation the mirror only ever saw one half of. A function could already tell you it was
used by a button; now the button tells you which function it runs, and the function's name in the
Buttons table opens it. Both directions work in the panel and in both exports.

## A function is joined to the module it exists for

In the wiring diagram, a function that exists *because of* a module - the one behind a custom button,
an approval or a validation rule - used to float unattached to it: the drawing held the function and
held the module and drew nothing between them. It draws the line now. On a real org of this size that
is about twenty functions which no other path in the picture connected to anything.

Buttons are deliberately not boxes of their own. On the org this was measured against there were
eighteen buttons and eighteen distinct functions, one to one, so a button box would have been one more
rectangle saying what the function box already says.

## Opening an export

After an export, the file name is followed by an **Open** button that opens the report in a window of
its own. It goes away with the message that carried it, and any click anywhere in the panel puts it
away - the same on every tab.

## Fixes

- The HTML report carried no Custom buttons section, while the panel and the Markdown report both
  did. Anything the panel shows about an item belongs in both reports; this one did not arrive.
- A blueprint named under a function's "Used in" linked to the module instead of to the blueprint, so
  the reader clicked a process and landed on a field table.
- In the buttons table, "Runs" printed `custom_function` - Zoho's word for "there is one" - instead of
  the function id, whenever the function was not part of the export.
- The Markdown report said a function was used in a button without saying in which module, which is
  the only way to find it again in a flat document.
- Clicking a button's name from a function opened the module but left you on Fields, with the Buttons
  tab unselected beside you.
- A function's name shown on any tab other than Functions could report "not in workspace - pull
  functions first" about a function that was in the mirror, if the panel had opened on another tab or
  the workspace had just been changed.
- A module whose buttons Zoho declined to answer for looked exactly like a module with none. It now
  says which of the two happened.
- The diagram could draw a second module box carrying the same name as a real one, because Zoho names
  the module in that reply by its translated label.
- Writing the sample workspace twice in one session listed the same button twice under a function.
