# Zoost CRM 2.0.2

Everything here came from one afternoon of somebody using the product on a real org and saying what
looked wrong. Nothing in it changes what a pull reads or what lands on your disk.

**The panel no longer tells you there is nothing here when there is.** Opening Zoost with no Zoho CRM
tab could cover the whole window with «Not on a Zoho CRM tab» and offer two ways on - go to Zoho, or
write a sample workspace - over a workspace with hundreds of functions already mirrored. The only
thing actually missing was the folder permission, which Chrome drops between sessions. The panel now
says that, and one click anywhere restores it; the full-window message is kept for a panel that
really has nothing in it.

**The detail pane says it is reading.** Opening an item reads the source, the call graph, the module
index and the related-list files, and until now the pane went on showing the *previous* item while
that happened: you clicked and nothing changed. There is a spinner over the pane from the moment you
click - including the moment before the Functions list has been built, which on a large org is the
longest part of the wait. If a read takes more than two seconds it says how long it has been
waiting. It never says why: a slow read has several causes and naming the wrong one would send you
to fix something that is not broken.

**Changing tab no longer leaves the previous tab's item on screen.** An item opened just before you
switched finished opening afterwards and drew itself over the new list - a function's code beside the
Modules list, and it would not go away. Changing tab now cancels the read that was in flight.

**A link to a function this mirror does not have says so.** From a connection's detail, clicking one
of the functions that use it could take away the item you were looking at and flash a read error that
the next line overwrote - a function renamed or deleted in Zoho is still named by the call graph.
Those links now go through the same four questions every other cross-tab link asks, and say which
absence it is.

**Two long operations say how far they have got.** Building the call graph reads every function that
its summary does not cover, and the export reads every function in the workspace; both used to print
one line and go quiet for as long as it took. They count now.

**If opening an item is slow, the working folder is worth a look.** Measured on a real org: 1.9s to
open a function whose file a sync service was keeping in the cloud, 17ms for one already on the disk.
Nothing in Zoost can change the first of those - it is the file being fetched - and the guides now
say so, with the remedy.
