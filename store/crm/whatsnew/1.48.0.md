**Java, Python and Node functions are mirrored whole.** The previous version could name them; this
one keeps them. Zoho serves those functions as projects rather than as one script, so Zoost reads the
file list, downloads every file and writes the structure under the function's namespace - directories
and subdirectories included, even the empty ones. A **Files** tab shows that structure as a tree you
can open and close, and any file in it opens under **Code**. Their source is coloured like Deluge is,
in both the panel and the HTML report. Full-text search reads every one of those files.

**The list knows the four languages.** A **Language** filter beside Type - Deluge, Java, Node.js,
Python, and it appears only where there is more than one - a sort by language, and the language on
each row. The versions Zoho spells out, `java17` or `nodejs_22`, stay on the row's tooltip and in the
reports: the menu is for choosing, the record is for keeping.

**Whether Zoho is actually running a compiled function.** They are written, saved and then
*published*, so the source in a mirror can be code your org has never run - and on disk the two look
identical. Each one now says `Live`, `Draft` for one that was never published, or `Draft +` for one
published with a later edit that is not live yet, with the publication date in its details and in
both reports.

**"Open in Zoho" opens the function, not the list.** Zoho's newer functions interface addresses a
function by an id from its own module, which is not the id a mirror holds. The pull now asks Zoho for
the pair and keeps it, so the button goes straight to that function. Where the mapping is missing -
an org still on the old interface, a role without that module - it opens the functions list exactly
as before.

**What your org actually runs, over a month.** The runtime reading was the last 24 hours, which
answers "is something failing now" and not "what does this org run": on a real org the busiest
function shows four figures over a month and single digits over a day. The health view now lists the
busiest functions over thirty days as well, with the window Zoho says it counted, and both reports
carry it.

**And what one function did lately.** In a function's details, **Runtime in Zoho** asks for that
function's last executions - when, from what, whether they worked and how many milliseconds each took
- and its revision history. Pick the window beside it: last 24 hours, today, yesterday, last 30 days,
or any span between two days from a calendar that will not offer a day outside the thirty Zoho keeps.
It is read when you press it, and it is not stored.

**"Refresh N outdated" that came back after every pull.** Eight functions stayed marked as needing a
re-download no matter how many times they were fetched. The sidecar on disk and the summary the panel
reads on opening were written from two different memories of the same download, and disagreed about
it for ever. They are written from what actually reached the disk.

**Sorting by size is gone.** The list could be ordered by bytes while the row showed a line count, so
a correct order read as a broken one - a sixteen-line function holding one enormous line sat above
functions with hundreds. Every sort the list offers is now something the row shows.

Plus the sample workspace gained one function per compiled language, so all of this can be tried on
invented data without connecting anything.
