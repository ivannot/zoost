**Zoost now works properly for a Zoho user who is not an administrator.** That was tested for the
first time in this version's making, and most of what follows came out of it.

**A function whose source Zoho will not show you.** Some roles can list the functions and not read
them. Those rows keep their name, namespace and language, carry a grey `⊘` with the day it was
asked, and are no longer counted by **Complete missing** - a button offering to fetch something Zoho
has already refused could only be refused again. Both reports say the same rather than «not
downloaded - run Pull all», which was advice that could not work. A pull re-asks every one of them,
so a role that has since been granted clears itself.

**An area Zoho refuses now says so in plain words.** The connections catalogue answers a token error
to a user it will not serve, and Zoost used to print that error with the list of cookies in your
browser - alarming, and wrong. It checks whether the same token is being accepted by its other reads:
if it is, the token is not the problem, and you are told that instead. The tab stays, later pulls
retry it, and the offer to look for a released fix is gone, because there is nothing to fix.

**Ask Zoho again about an area it refused.** A role refusal is recorded per workspace and later pulls
skip it - re-asking an answered question on every pull is a thousand pointless requests for one role
change. So **⚙ Settings → Tabs** has an **ask again** tick on a refused row: tick it, press
**Save tabs**, and the next **Pull all** includes that area once. The tab comes back if Zoho grants
it. Before, nothing could ask again and two sentences said otherwise.

**An empty tab says what Zoho last answered about it**, rather than «nothing pulled yet» about an
area that was pulled and refused.

**A Save that has something to save says so.** Every section's Save used to look the same whether or
not there was anything to store. It now lights up, with **Unsaved changes** beside it, only while
what is on screen differs from what is saved - put a change back the way it was and both go. Turning
a tab back on also restores the pull switch that hiding it turned off.

**And the Live / Draft state stays put.** It was read from a file only a Refresh opens, so it
appeared after one and was gone the next time the panel opened - on the sample workspace it never
appeared at all. A workspace saved before this version is re-read once, automatically.

Plus: the sample workspace no longer opens with 120 rows marked as outdated; a Language filter no
longer follows you into the next workspace; **Runtime in Zoho** no longer goes blank if you toggle
names while it loads; and a workflow or actions area your role cannot read is now recognised as a
refusal rather than reported as a broken read.
